  Payment fee:
    Zelle  → no fee  (order_total = order_base_total)
    PayPal → +4% fee (order_total = order_base_total × 1.04)

  Formula:
    plan_subtotal    = plan_price × doc_count
    addons_subtotal  = Σ (translation_cost + scan_cost) per doc
    order_base_total = plan_subtotal + addons_subtotal + shipping_cost
    order_total      = order_base_total  [Zelle]
                     = order_base_total × 1.04  [PayPal]

  ── CRITICAL (Security / Data Integrity) ──────────────────────────────────────

  [C1] ALL PRICING IS CLIENT-SIDE ONLY
       Problem  : Every total (plan_subtotal, addons_subtotal, order_total) is
                  calculated in the browser JavaScript and sent as plain text.
                  A crafted curl request can send order_total=$1.00 for a $755
                  order and n8n will accept it silently.
       Evidence : All 8 tests sent manually calculated values — n8n accepted them
                  without any server-side verification.
       Fix      : Add PHP server-side price re-calculation in order-form.php
                  before forwarding to n8n. If client total differs from PHP
                  total by more than $0.01, reject the submission or flag it.
       File     : order-form.php (lines 2430–2439, fd.append total fields)

  [C2] EXPRESS PLAN RESTRICTIONS ARE UI-ONLY (scan + translation)
       Problem  : The browser disables scan and translation checkboxes on Express
                  plan, but a raw curl POST can still send doc_1_scan=yes or
                  doc_1_translate=yes on an Express order. n8n will receive and
                  process these without complaint.
       Evidence : T3 and T8 manually sent scan=no (correct), but nothing
                  server-side would stop sending scan=yes.
       Fix      : Add a PHP guard before the webhook call — if selected_plan is
                  "express", force all doc_N_scan=no and doc_N_translate=no.
       File     : order-form.php (PHP section, before the fetch call)

  [C3] PAGE COUNT IS CLIENT-SIDE AND UNVERIFIED
       Problem  : T4 sent doc_1_pages=2 while the actual uploaded file was a
                  1-page PDF. n8n accepted this without question. Since
                  translation cost = $60 × (effective_pages + 1), a falsified
                  page count directly inflates or deflates the translation price.
       Fix      : Add server-side PDF page counting in PHP using regex on the
                  uploaded binary (same /Type\s*\/Page/ approach used client-side)
                  and recalculate translation costs from the verified count.
       File     : order-form.php (PHP file handling section)

  ── DATA QUALITY (n8n / Google Sheets) ────────────────────────────────────────

  [D1] DUPLICATE SUBTOTAL FIELD
       Problem  : Both doc_subtotal and addons_subtotal are sent with the same
                  value (e.g., $200.00). This creates confusion in n8n and
                  Google Sheets — which one is authoritative?
       Fix      : Remove doc_subtotal. Keep addons_subtotal (more descriptive).
       File     : order-form.php line 2376 (fd.append doc_subtotal)

  [D2] DUPLICATE PHONE FIELD
       Problem  : Both phone_number (digits only, e.g., "5551234001") and phone
                  (full with code, e.g., "+1 5551234001") are sent. The number-
                  only field has no use if the full field exists.
       Fix      : Remove phone_number. Keep phone (E.164-style full number).
                  Same for return_phone_number / return_phone.
       File     : order-form.php lines 2364 and 2426

  [D3] FILE SIZE SENT AS STRING WITH UNIT
       Problem  : doc_N_file_size is sent as "303 bytes" (string). Google Sheets
                  cannot SUM or average this without text parsing.
       Evidence : All 8 tests sent "303 bytes", "481 bytes", "659 bytes".
       Fix      : Send as a plain integer (e.g., 303). Add a separate unit label
                  in n8n if needed (Set node: file_size_unit = "bytes").
       File     : order-form.php line 2383

  [D4] COVER PAGE "NOT ANSWERED" STATE
       Problem  : When a user doesn't answer the cover page question (most docs),
                  the value sent is the string "not answered". This is awkward
                  to filter in Google Sheets (not a standard null/empty/boolean).
       Fix      : Change to empty string "" or "unknown". Or make the question
                  mandatory whenever translation is enabled.
       File     : order-form.php line 2393

  [D5] ZELLE FIELD NAME MISMATCH
       Problem  : The field is named zelle_payer_email, but the UI label reads
                  "Enter your Zelle email or phone number". Phone numbers like
                  +15551234567 will be stored in a field named "email".
       Evidence : T8 used chenwei.pay88@gmail.com — an email. But the field
                  would also accept +86 13812340008.
       Fix      : Rename to zelle_payer_id. Optionally add zelle_payer_id_type
                  (values: "email" or "phone") for cleaner data.
       File     : order-form.php lines 2448, and matching n8n/Sheets column

  [D6] NO ORDER STATUS FIELD
       Problem  : n8n receives no starting status for the order. It has to infer
                  "new order" from the fact it just received the webhook.
       Fix      : Add -F "order_status=pending" to every submission. n8n can
                  then update this to "confirmed", "processing", "shipped", etc.
       File     : order-form.php (new fd.append near submitted_at)

  [D7] ORDER REFERENCE USES LOCALSTORAGE COUNTER
       Problem  : The ORD-### counter is stored in localStorage and resets when
                  the browser clears data, uses incognito mode, or a new device.
                  Two customers could both get ORD-001-260526.
       Fix      : Generate the order ref server-side using PHP with a database
                  auto-increment or atomic file-based counter. Return it to the
                  client for display.
       File     : order-form.php (replace localStorage counter logic)

  ── MINOR / NICE-TO-HAVE ──────────────────────────────────────────────────────

  [M1] DRAWN SIGNATURE SIZE IN PRODUCTION
       In all tests, the drawn signature was a minimal 1×1 PNG (~88 bytes of
       base64). Real user drawings on the canvas can be 50–200KB of base64 text
       being sent as a form field string. Consider saving the signature as a file
       upload or to cloud storage and sending only the URL to n8n.

  [M2] PAYPAL PAYMENT NOT TESTED
       All 8 tests used Zelle. PayPal requires a live PayPal transaction
       (orderID + transactionID from the PayPal SDK). These fields cannot be
       faked without a real PayPal sandbox transaction. Browser-based testing
       is required for full PayPal coverage.

  [M3] WEBHOOK URL IN CONFIG.PHP IS STILL TEST URL
       config.php line 7 still points to /webhook-test/upload_form.
       The live form will fail for real users until this is updated to:
       define('N8N_UPLOAD_FORM', 'https://usauth.app.n8n.cloud/webhook/upload_form');

  [M4] NO SERVER TIMESTAMP IN N8N
       submitted_at is browser-generated (UTC via toISOString()). Consider
       adding a server_received_at timestamp in the n8n workflow via a Set node
       so you have an independent audit timestamp.

  [M5] SCAN COST FORMATTING INCONSISTENCY
       doc_N_scan_cost is sent as "$10" (no decimal) while all other money
       fields use "$10.00" format. Normalize to two decimal places for
       consistent Google Sheets import.
       File: order-form.php line 2398
